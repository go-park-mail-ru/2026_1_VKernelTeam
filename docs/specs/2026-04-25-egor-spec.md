# Спецификация Егора: Ядро обращений техподдержки

**Дата**: 2026-04-25 | **Хакатон** | **Дедлайн демо**: 18:00
**Зона ответственности**: iframe-виджет, создание/просмотр/редактирование обращений, категории, статусы

---

## 1. Что нужно сделать

Егор реализует полный стек ядра техподдержки:
- Бэкенд: миграция БД, модель, репозиторий, сервис, HTTP-хендлеры для CRUD обращений
- Фронтенд: iframe-виджет с кнопкой-триггером, форма создания, список и детали обращений

## 2. Общая схема

```
Основная страница (clover-go.ru)
  └── Кнопка-триггер (position: fixed, правый нижний угол)
        └── iframe (clover-go.ru/support-widget)
              └── Мини-SPA
                    ├── Список обращений
                    ├── Форма создания
                    └── Детали обращения
                          └── <div id="chat-container"></div>  ← сюда Николай встроит чат
```

## 3. Бэкенд (Go)

### 3.1 Миграция БД

**Создаётся ПЕРВОЙ** (до миграции Николая, т.к. его таблица ссылается на `support_ticket`).

Файл: `migrations/XXXXXX_create_support_ticket.up.sql`
```sql
CREATE TABLE support_ticket (
    id            SERIAL PRIMARY KEY,
    user_id       INT NOT NULL REFERENCES "user"(id),
    category      VARCHAR(50) NOT NULL,   -- 'bug', 'suggestion', 'complaint'
    status        VARCHAR(50) NOT NULL DEFAULT 'open',  -- 'open', 'in_progress', 'closed'
    title         VARCHAR(255) NOT NULL,
    description   TEXT NOT NULL,
    created_at    TIMESTAMP DEFAULT NOW(),
    updated_at    TIMESTAMP DEFAULT NOW()

```

### 3.4 Сервис (usecase)

Файл: `internal/usecase/support_ticket_service.go`

Бизнес-правила:
- Категория должна быть одной из: `bug`, `suggestion`, `complaint`
- Обновлять обращение может только его автор и только в статусе `open`
- `GetMyTickets` возвращает только обращения текущего пользователя (user_id из JWT)
- `GetTicket` — доступ для автора или пользователя с ролью `support`/`admin`

### 3.5 HTTP-хендлеры

Файл: `internal/delivery/handlers/support_ticket_handler.go`

| Метод | Путь | Описание |
|-------|------|----------|
| POST  | `/api/v1/support/tickets` | Создать обращение |
| GET   | `/api/v1/support/tickets` | Мои обращения (user_id из JWT) |
| GET   | `/api/v1/support/tickets/{id}` | Детали обращения (своё или админ) |
| PUT   | `/api/v1/support/tickets/{id}` | Обновить (своё, только open) |

Регистрация в `setupRoutes()` (`internal/app/http/`):
```go
router.HandleFunc("POST /api/v1/support/tickets", authMiddleware(handler.CreateTicket))
router.HandleFunc("GET /api/v1/support/tickets", authMiddleware(handler.GetMyTickets))
router.HandleFunc("GET /api/v1/support/tickets/{id}", authMiddleware(handler.GetTicket))
router.HandleFunc("PUT /api/v1/support/tickets/{id}", authMiddleware(handler.UpdateTicket))
```

## 4. Фронтенд (TypeScript + Handlebars)

### 4.1 Iframe-виджет на основной странице

**Кнопка-триггер:**
- Добавляется в корневом `app.ts` (или `header`)
- `position: fixed; right: 20px; bottom: 20px; z-index: 9999`
- Иконка вопросительного знака / чата
- По клику — toggle видимости iframe (display: none / block)

**Iframe:**
- `<iframe src="/support-widget" id="support-iframe">`
- `position: fixed; right: 20px; bottom: 80px; width: 400px; height: 500px; z-index: 9998`
- `border-radius: 12px; box-shadow: 0 4px 20px rgba(0,0,0,0.15)`
- Скрыт по умолчанию

**Авторизация в iframe:**
- Родительская страница при загрузке iframe отправляет JWT-токен через `window.postMessage`
- Iframe слушает `window.addEventListener('message', ...)` и сохраняет токен
- Все API-запросы из iframe используют этот токен

### 4.2 Webpack: отдельный entry point

В `webpack.config.js` добавить:
```js
entry: {
  app: './src/js/app.ts',              // существующий
  'support-widget': './src/js/support-widget.ts'  // новый
}
```

Отдельный HTML: `public/support-widget.html`

### 4.3 Страницы виджета

**Список обращений (главная виджета):**
- Карточки: иконка категории + заголовок + статус-бейдж + дата
- Статус-бейджи: open (зелёный), in_progress (жёлтый), closed (серый)
- Кнопка "Создать обращение" сверху
- Клик по карточке → переход к деталям
- Если обращений нет — заглушка "У вас пока нет обращений"

**Форма создания:**
- Select: категория — Баг / Предложение / Жалоба
- Input: заголовок (обязательное, макс 255 символов)
- Textarea: описание (обязательное)
- Кнопка "Отправить"
- Валидация на клиенте: все поля обязательны, заголовок не длиннее 255
- После успешной отправки — редирект на список обращений

**Детали обращения:**
- Полная информация: категория, статус-бейдж, заголовок, описание, дата создания
- Кнопка "Редактировать" (видна только если статус `open`)
- Кнопка "Назад" → список
- **`<div id="chat-container"></div>`** — пустой контейнер, куда Николай встроит чат

### 4.4 Файловая структура

```
src/modules/support/
  ├── controllers/
  │   ├── supportWidgetController.ts   -- основной контроллер виджета (роутинг внутри iframe)
  │   ├── ticketListController.ts      -- список обращений
  │   ├── ticketCreateController.ts    -- форма создания
  │   └── ticketDetailController.ts    -- детали обращения
  ├── views/
  │   ├── widget-layout.hbs            -- layout виджета (header + content area)
  │   ├── ticket-list.hbs              -- список карточек
  │   ├── ticket-create.hbs            -- форма создания
  │   └── ticket-detail.hbs            -- детали + #chat-container
  ├── api/
  │   └── supportApi.ts                -- API-клиент для /api/v1/support/tickets
  └── styles/
      └── support.css                  -- стили виджета

src/js/support-widget.ts              -- entry point для iframe
public/support-widget.html            -- HTML для iframe
```

### 4.5 Точки интеграции

- В `app.ts` или `header` — рендер кнопки-триггера и iframe
- В `webpack.config.js` — entry `support-widget`
- В `server/server.js` — роут `/support-widget` должен отдавать `support-widget.html`
- **Для Николая**: в `ticket-detail.hbs` оставить `<div id="chat-container"></div>`
